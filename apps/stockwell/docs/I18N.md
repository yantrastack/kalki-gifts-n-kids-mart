# I18N.md — Internationalization & currency

Both apps support **English** and **Telugu (తెలుగు)**, built for Indian
customers. This doc covers the pattern; the whole-repo overview is in
[`../../../AGENTS.md`](../../../AGENTS.md).

## Where strings live

All user-facing text lives in per-app dictionaries — nowhere else:

| App | Files |
| --- | --- |
| Stockwell (admin) | `src/i18n/en.ts`, `src/i18n/te.ts`, `src/i18n/index.tsx` |
| Storefront (customer) | `src/i18n/en.ts`, `src/i18n/te.ts`, `src/i18n/index.tsx` |

`en.ts` exports `en` and `export type Dict = typeof en`. `te.ts` is declared
`export const te: Dict = {...}`, so **any missing or misspelled key is a compile
error** (`pnpm typecheck`). Keep the two files structurally identical.

## Using translations

```tsx
const { t, lang, setLang } = useI18n();

t("nav.dashboard")                       // simple lookup
t("nav.seats", { plan, seats })          // {name} interpolation
t("cart.items", { count })               // → cart.items_one / cart.items_other
```

- **Lookup:** dot-path into the current language, falling back to English, then
  to the raw key (so a missing string is visible, never a crash).
- **Interpolation:** `{name}` placeholders are filled from the params object.
- **Plurals:** pass `count`; the resolver prefers `key_one` (count === 1) or
  `key_other`, else the bare key.

## Providers

- Stockwell: `LanguageProvider` wraps the app in `src/app/layout.tsx`. It starts
  on `en` for SSR + first client render (avoids hydration mismatch), then adopts
  the `localStorage` choice on mount, and sets `<html lang>`.
- Storefront: `I18nProvider` wraps `<Shop />` in `App.tsx`. Persists to
  `localStorage` on web; no-ops on native.

A segmented **EN / తె** toggle lives in each app's header/top bar
(`AppShell.tsx` `LangToggle`; storefront `App.tsx` `LangToggle`).

## Gift-finder reasons (structured, translatable)

`GET /api/shop/gift-finder` must **not** return English sentences. It returns
`GiftReason[]` — structured codes from `@stockwell/shared`, e.g.
`{ code: "occasion", value: "birthday" }`. The storefront turns each into a
localized string with `giftReason()` (in `src/i18n/index.tsx`), which looks up
the reason template and the enum-value label (`gift.occasion.birthday`, …) in the
active language. Add new reason codes in both the shared type and the `reason`
dictionary.

## Currency (₹, Indian formatting)

- Shared `money(currency, amount)` and stockwell `fmt.money(n, cur="₹")` use
  `en-IN` grouping → `₹1,25,000.00` (lakh/crore). `fmt.moneyCompact` abbreviates
  to `k` / `L` / `Cr`.
- The symbol comes from the `currency` setting (default `₹`), surfaced by
  `/api/brand` and consumed by both apps. Change it in **Settings → Currency
  symbol**, not in code.
- Never hardcode `$` or `en-US` for money.

## Adding a language

1. Create `src/i18n/xx.ts` as `export const xx: Dict = {...}` (typecheck guides
   you through every key).
2. Register it in `src/i18n/index.*`: add to `DICTS` and `LANGS`.
3. The toggle renders all `LANGS` automatically.

## Coverage & how to extend

- **Storefront:** fully translated.
- **Stockwell:** chrome (nav, top bar, login) is translated. To localize an admin
  page, add a namespace to `en.ts`/`te.ts` and replace literals with `t(...)`.
  Do it page-by-page; the fallback keeps untranslated keys readable meanwhile.
