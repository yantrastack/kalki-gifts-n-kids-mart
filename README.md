# Stockwell — Kanuka Gifts

Shop-in-a-box for a local Indian gift shop, as a pnpm workspace.

| Package | What it is |
| --- | --- |
| [`apps/stockwell`](apps/stockwell) | **Admin + backend** — inventory, POS, orders, staff, engagement. Next.js 15 (App Router) + Drizzle ORM (libSQL/SQLite). Also serves the public shop API and product media. |
| [`apps/storefront`](apps/storefront) | **Customer app** — browse, Discover reels, cart, order via WhatsApp/call. Expo (React Native + web). |
| [`packages/shared`](packages/shared) | `@stockwell/shared` — the API contract + formatting helpers shared by both apps. |

**Features:** inventory + POS · public storefront · **product photos & videos** ·
**Discover** (Instagram-style reels feed with likes/shares/buys) · **engagement
analytics** · a **Gift Finder** (recommendations from admin-tagged attributes) ·
**English + Telugu** throughout · **₹ rupee** pricing (Indian lakh/crore). Orders
are placed by WhatsApp/phone — no online payment.

## Prerequisites

- **Node.js 20+** (developed on 22).
- **pnpm 11** — the repo pins it via `packageManager`. Easiest install:
  ```bash
  corepack enable && corepack prepare pnpm@11.3.0 --activate
  ```
- No database or cloud account needed — it runs on a local SQLite file.

## Quick start

```bash
# 1. install everything (workspace-aware)
pnpm install

# 2. (optional) create the env file — local defaults work without it
cp apps/stockwell/.env.example apps/stockwell/.env

# 3. create + migrate + seed the local SQLite database (once)
pnpm db:setup

# 4. run the admin + backend  →  http://localhost:3050/admin
pnpm dev
```

> In production both apps are served by the one Next app — storefront at `/`,
> admin at `/admin`. In dev, use `/admin` for the admin and run the storefront
> separately (below) for hot reload. See [DEPLOY.md](DEPLOY.md).

In a **second terminal**, run the customer app:

```bash
pnpm dev:storefront        # Expo dev server
```

Then either:
- press **`w`** to open the storefront in a **web browser** (http://localhost:8081), or
- scan the QR code with **Expo Go** on your phone (see "Phone" below).

Both apps must run together — the storefront reads live data from the stockwell
backend on port 3050.

## How the two apps connect

The storefront calls the stockwell backend's **public** endpoints: `/api/brand`,
`/api/shop/products`, `/api/shop/feed`, `/api/shop/gift-finder`, `/api/shop/events`,
and product media under `/uploads/*` and `/seed/*`.

| App | Dev URL |
| --- | --- |
| stockwell admin + API | `http://localhost:3050/admin` |
| storefront (web, hot reload) | `http://localhost:8081` (Expo) |

In production it's one deployment: storefront at `/`, admin at `/admin`, API at
`/api` (all same origin).

**On a physical phone (Expo Go):** your phone can't reach `localhost`, so point it
at your computer's LAN IP:

```bash
EXPO_PUBLIC_API_BASE=http://<your-computer-LAN-IP>:3050 pnpm dev:storefront
```

(See [apps/storefront/src/api.ts](apps/storefront/src/api.ts).)

## Common commands

```bash
pnpm dev               # stockwell admin + API (port 3050)
pnpm dev:storefront    # expo storefront (press w for web, or scan for Expo Go)
pnpm build             # production build of stockwell (also the typecheck gate)
pnpm typecheck         # tsc --noEmit across all packages
pnpm check             # Biome lint + format check (CI gate)
pnpm check:write       # apply Biome fixes + format

pnpm db:setup          # generate + migrate + seed (fresh demo data)
pnpm db:seed           # re-seed only (wipes & refills)
pnpm db:generate       # new migration after editing apps/stockwell/src/db/schema.ts
pnpm db:migrate        # apply migrations
```

## Configuration

- **Database** — local SQLite at `apps/stockwell/local.db` (gitignored,
  regenerated by `db:seed`). To use Turso in production, set `DATABASE_URL` +
  `DATABASE_AUTH_TOKEN` in `apps/stockwell/.env` (template in `.env.example`).
- **Auth secret** — `SESSION_SECRET` in `.env` (has a dev default; set a real one
  for production).
- **Language** — switch with the **EN / తె** toggle in either app's header.
- **Currency / branding** — edit in the admin under **Settings** (currency
  defaults to `₹`).
- **Media hosting** — uploads go to local disk by default. For production, plug in
  **Cloudinary** (free tier, images + video) via env vars — see
  [apps/stockwell/docs/MEDIA.md](apps/stockwell/docs/MEDIA.md).

## Deploying

See **[DEPLOY.md](DEPLOY.md)** — **one** Vercel project serves both apps (`/` +
`/admin`). Build command `pnpm build:full` exports the storefront and embeds it
into the Next app. Note: Vercel's filesystem is ephemeral, so production needs
**Turso** (hosted SQLite) + **Cloudinary** (media) instead of the local file/disk
defaults.

## Troubleshooting

- **Storefront can't reach the shop** — make sure `pnpm dev` (port 3050) is
  running, and on a phone set `EXPO_PUBLIC_API_BASE` to your LAN IP (above).
- **Port 8081 already in use** — another Expo app is running; stop it, or start
  the storefront on another port: `pnpm --filter storefront exec expo start --web --port 8090`.
- **"missing required error components" in the admin** — Turbopack's dev cache got
  corrupted (usually from running `pnpm build` while `pnpm dev` was live). Stop
  the dev server, `rm -rf apps/stockwell/.next`, and restart. Don't run `build`
  while `dev` is running.

## Conventions

- Cross-app types live in `@stockwell/shared` — never redeclare them in an app.
- User-facing text lives only in the i18n dictionaries
  (`apps/*/src/i18n/{en,te}.ts`); money uses the shared `money()` / `fmt.money()`
  helpers (₹, `en-IN`) — never a hardcoded `$`.
- Lint + format is [Biome](https://biomejs.dev): **single quotes**, 2-space
  indent, 100 cols. Run `pnpm check:write` before committing.
- `.npmrc` pins `node-linker=hoisted` (Metro needs a flat `node_modules`) — keep it.
- Deeper docs: [`AGENTS.md`](AGENTS.md), [apps/stockwell/CLAUDE.md](apps/stockwell/CLAUDE.md),
  and [apps/stockwell/docs/](apps/stockwell/docs) (architecture, data model, API,
  i18n, media).
